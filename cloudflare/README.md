# Сервер на Cloudflare Workers — прототип

Цель — уйти с дроплета DigitalOcean. Вопрос прототипа: собирается ли наш код под Workers и
укладывается ли в бесплатные лимиты. Пишет только в свою ветку `cf-proto` репозитория
`dimmik/tc-strg-test` (её делает сам, от `master`); `master` — бета, второй писатель потерял
бы правки.

Ветка кода `cf/worker-proto` (не `beta/*`: сборку беты не трогает). Адреса:
<https://tc-proto.dimmik-a.workers.dev> (Rust, хранилище GitHub, клиент как статика) и
<https://tc-proto-mongo.dimmik-a.workers.dev> (JS, проверка Mongo).

## Что в нём

### `worker/` — Rust, [`workers-rs`](https://github.com/cloudflare/workers-rs) 0.8.7

Крейт вне workspace `rust/`. Один Durable Object `Store` на всё хранилище — как процесс
сервера: держит в памяти список файлов ветки, кладёт прочитанные файлы в своё хранилище SQLite
по git sha (кэш на диске сервера), пишет один.

- `GET /api/Info/version` — Worker сам по себе.
- `GET /api/Tour/:id` — тур: из ждущих записи, из хранилища объекта или из GitHub.
- `PUT /api/Tour/:id` — тур проверяется (`Tour::from_json`, id), запечатывается и ждёт;
  таймер объекта (alarm) через 30 с пишет всё ждущее одним коммитом (5 запросов к GitHub при
  любом числе файлов) — как `GitHubFlushSeconds` у сервера.
- `GET /calc/:id` — балансы и предложение расчёта (`tc_core::calc`) в объекте;
  `GET /calc-here/:id` — то же в самом Worker-е.
- `GET /push-test?n=N` — N push-уведомлений, сделанных как у сервера (`web-push-native`:
  VAPID-подпись, шифрование под ключ браузера), отправленных в FCM на несуществующие
  подписки. Ключи свои, случайные, не серверные.
- `GET /status` — что ждёт, последний коммит, последняя ошибка.
- Клиент (`rust/crates/tc-web/dist`) — статикой Workers: `[assets]`, SPA-ответ для
  `/tour/...`, API — в Worker (`run_worker_first`).

Шифрование — тот же `tc-server/src/github/seal.rs`, подключённый `#[path]`, не копия.
`tc-core` и `web-push-native` — без правок.

Секреты (`wrangler secret put`): `GITHUB_TOKEN` (запись в репозиторий данных), `STORE_KEY`
(`GitHubStoreKey`).

### `mongo/` — JS, официальный драйвер `mongodb` 7.7.0

`nodejs_compat`, TCP-сокеты Workers. `GET /` — подключение к кластеру прода по публичному
SRV-имени (`dimmik-mongo-4su6a.azure.mongodb.net`, есть в старом C#-коде) и команда `hello`,
на которую Mongo отвечает до входа. **Без логина и пароля** — учётных данных прода прототип не
знает. `GET /tcp?host=…` — голый TLS-сокет к одному узлу.

## Как собрать и выложить

Нужны Node (`wrangler` 4.155.0 — в `package.json`) и `worker-build` (`cargo install
worker-build --version 0.8.7 --locked`), toolchain как у сервера (`RUSTUP_TOOLCHAIN=1.98.1`),
собранный клиент (`trunk build --release` в `rust/crates/tc-web`).

```
cd cloudflare/worker      # или cloudflare/mongo
npm install
CLOUDFLARE_ACCOUNT_ID=… CLOUDFLARE_API_TOKEN="$(cat <файл>)" npx wrangler deploy
CLOUDFLARE_ACCOUNT_ID=… CLOUDFLARE_API_TOKEN="$(cat <файл>)" npx wrangler tail tc-proto --format json
```

В логе `wrangler tail` у каждого вызова — `cpuTime` и `wallTime` (мс), отдельно у Worker-а
и у объекта. Статика Worker не запускает и в логе не видна.

## Mongo

- **Rust-драйвер под Workers не собирается:** `mongodb` 3 тянет tokio с сетью, а `mio`
  отказывается: «This wasm target is unsupported by mio». Значит, Mongo из Rust-Worker-а —
  только через JS: драйвер на JS, а Rust зовёт его через wasm-bindgen.
- **JS-драйвер работает:** подключился к кластеру прода (MongoDB 8.0, три узла, SRV через
  DNS Workers), `hello` отвечен. Atlas пускает адреса Cloudflare — список доступа открыт.
- **Но каждое подключение — 20–24 мс процессора и ≈ 300 мс** (TLS к узлам, обнаружение
  набора реплик) **ещё до входа**; вход (SCRAM-SHA-256) добавит своё. Worker не держит
  соединение между запросами, так что это — на каждый запрос, вдвое больше 10 мс бесплатного
  тарифа. Держать соединение может объект (пока жив), но и он засыпает.
- **Вход и чтение не проверены:** нужен пользователь Atlas — лучше отдельный, только на
  чтение — и его пароль через secret-drop.

## Что из этого следует

- **Код переносится.** `tc-core`, шифрование хранилища и push собрались под Workers без
  правок. Переделывается только среда: `tokio`/`reqwest`/`axum`/диск → `fetch`, Router,
  хранилище объекта, alarm.
- **Всё тяжёлое — в объекте**, Worker только передаёт запрос. Объект и так нужен: один
  писатель с памятью и коммитом по таймеру. Тогда 10 мс Worker-а не встречаются, а у объекта —
  до 30 с на запрос; самое тяжёлое из замеренного (50 push) — 0,3 с.
- **Хранилище GitHub подходит Workers лучше Mongo:** HTTP-запросы, а не соединения;
  коммит — 5 запросов из 50 разрешённых. Mongo возможна, но через JS и с ≈ 20+ мс и 300 мс на
  запрос.
- **Клиент — статикой Workers:** бесплатно, вне лимита запросов, Worker не запускается.
- **Не проверено:** перенос `/t` (≈ 1 800 строк на axum и состоянии сервера — разделить
  разметку и обработчики; процессор — как у балансов), вход в Mongo, сколько живёт прогретый
  объект и сколько стоит его пробуждение, отправка настоящих push (подписки беты), вход и
  права (`auth.rs`), подписки на push в хранилище.
