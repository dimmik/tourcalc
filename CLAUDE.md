# Правила работы с репозиторием

Для Claude Code (читается автоматически) и для любого, кто работает здесь так же. Здесь
только то, что верно на любой машине; настройки конкретной машины сюда не пишутся.

Где что: Rust-порт — [`rust/`](rust/): устройство — [`rust/GUIDE.md`](rust/GUIDE.md),
хроника решений — [`rust/README.md`](rust/README.md), отложенное —
[`rust/BACKLOG.md`](rust/BACKLOG.md). Ревью — `review-*.md` в корне.

## Git

- **Коммитить можно без спроса, пушить — только спросив.** Каждый пуш запускает сборку
  образов в GitHub Actions (`.github/workflows/docker-publish-*.yml`), а изменение обычно
  хотят сначала посмотреть локально. Сказать, что закоммичено, и спросить про пуш.
- **Перед пушем проверить ветку** (`git branch --show-current`): её меняют посреди работы, не
  предупреждая. Пушить ту, что сейчас выбрана; если ветка сменилась, назвать её в отчёте.
- **`[new branch]` при пуше и удалённые при `fetch --prune` ветки — норма.** Ветки удаляют
  на GitHub после мержа, а локально держат. Локальные ветки не чистить и не предлагать.
- **Автор коммитов** — `dmk <git@dimmik.org>`. Если идентичность в git не настроена,
  передавать её в команде (`git -c user.name=dmk -c user.email=git@dimmik.org commit …`), а
  не записывать в конфиг.
- **В сообщении коммита** — `Co-Authored-By: Claude …` можно, строку `Claude-Session: …` —
  нет: ссылка на сессию, которую никто больше не откроет, — шум в истории.
- **В описании PR** — ни «🤖 Generated with Claude Code», ни ссылки на сессию: только что
  было не так, что сделано и как проверено. PR открывать в `prod` по просьбе, мержить — не
  самим.
- **Концы строк**: в репозитории LF (`.gitattributes`), в рабочей копии на Windows — CRLF.
  Правя файл скриптом, сохранять те концы строк, что в нём уже есть.

## Журнал изменений для читателя

Всякое изменение, которое читатель может заметить, — в том же коммите добавляет строку в
[`rust/crates/tc-web/src/changes.html`](rust/crates/tc-web/src/changes.html): это
раскрывающийся «Change log» внизу страницы Help. По-английски, как весь интерфейс; сверху
новое, заголовок — дата. **Что** поменялось — жирным, коротко, словами читателя, а не кода;
**почему** — следующей фразой: что было не так и как это выглядело. Внутренности, которых
не видно (CI, рефакторинг, тесты, документация), туда не пишутся.

## Языки интерфейса

Клиент говорит по-английски и по-русски (`rust/crates/tc-web/src/i18n/`). **Каждая новая
строка интерфейса — сразу в оба языка**: поле в `Texts` (`i18n/mod.rs`), значение в `en.rs` и
в `ru.rs`; забытый язык не соберётся. Справка — два файла, `help.html` и `help.ru.html`,
правятся вместе. По-русски — без указания рода там, где имя может быть чьим угодно («платит»,
«получает», «вклад», а не «заплатил»). По-английски остаются: всё, что пишет сервер
(уведомления, строки версий, текстовые страницы `/t`), и журнал изменений.

## Что где держать

- **Всё, что может пригодиться снова, — в репозитории**: прототипы, скрипты для скриншотов и
  проверок, их исходные данные. Не в `C:\tmp` и не во временной папке сессии — их чистят.
  Прототипы — в [`prototypes/`](prototypes/), со своим README; пути в скриптах —
  относительно самого скрипта. Скрипты-помощники — в [`tools/`](tools/): скриншоты через
  headless Chrome — [`tools/browser/shot.py`](tools/browser/shot.py), как запускать — в его шапке.
- **Папка, которую никто не собирает, добавляется в `.dockerignore`** (`prototypes/` и `tools/`
  уже там): блазорный образ копирует весь репозиторий (`COPY . .`), и любая правка в ней
  пересобирала бы .NET.
- **Одноразовый результат** — скриншоты, профили браузера, логи — живёт вне репозитория и
  **удаляется после пуша, а не после коммита**: между коммитом и пушем изменение
  смотрят, и скриншот спрашивают тогда. Профили headless Chrome весят по ~200 МБ —
  их тоже удалять.

## Новая машина: чего не хватает — поставить

Если чего-то из списка нет, **поставить сразу**, а не обходить: без Mongo молча пропускаются
её тесты, без .NET нечем сверить поведение с приложением, без Docker образ проверяется
только пушем в CI. Спросить можно, но предложить установку, а не работу без инструмента.

| что | зачем | версия |
|---|---|---|
| Rust (`rustup`) + `rustup target add wasm32-unknown-unknown` | сервер и клиент | как в `tourcalc.rust.docker` (сейчас 1.98.1) |
| [trunk](https://github.com/trunk-rs/trunk/releases) | сборка wasm-клиента | `TRUNK_VERSION` оттуда же (сейчас 0.21.14) |
| .NET SDK | C#-приложение — эталон, с которым сверяется порт | `net8.0` (`TCBlazor/*/*.csproj`) |
| MongoDB | тесты `--features mongo`; CI гоняет их на `mongo:7` | 7.x |
| Docker + buildx, builder на драйвере `docker-container` | собрать образ так же, как CI (`setup-buildx-action` делает такой же) | любой свежий |
| Chrome | скриншоты и проверки через headless-режим | любой |

Mongo ставить **вне репозитория и вне временных папок** (они чистятся) — достаточно
распакованного архива и отдельной папки под данные; её не удалять при уборке. В WSL
.NET-приложение запускается Windows-вским `dotnet.exe`, а переменные вроде
`ASPNETCORE_ENVIRONMENT` надо выставлять на стороне Windows (через `.bat`) — экспорт в
WSL до Windows-процесса не доходит.

## Сборка и тесты

- `tc-web` — бинарный крейт: тесты — `cargo test -p tc-web --bins` (`--lib` не найдёт цели).
- Тестам Mongo нужен живой mongod: `TC_TEST_MONGO=mongodb://127.0.0.1:27017 cargo test -p
  tc-server --features mongo --test mongo`. Без переменной они молча пропускаются — зелёный
  прогон без неё Mongo не проверял.
- Образ собирается так же, как в CI: `docker buildx build -f tourcalc.rust.docker` с
  `--build-arg BUILD_TYPE/BUILD_ID/BUILD_COMMIT`, как в workflow.
